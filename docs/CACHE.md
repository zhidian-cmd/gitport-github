# 缓存体系全解

当前架构（2026-11-25）：三块缓存各管一段，互不依赖——**资产与 HTML 骨架落磁盘，全部 XHR 只住内存**。

---

## 0. 一句话总览

| 层 | 存什么 | 存在哪 | 寿命 | 一句话 |
| --- | --- | --- | --- | --- |
| 浏览器缓存 | githubassets 的 js/css/字体 | 浏览器自己的磁盘 | 一年 immutable | 请求都发不到代理，热身后日志里没有命中行是正常态 |
| 资产库 | githubassets 的 js/css/字体 | `.cache/assets/`（磁盘） | 20MB，按文件年龄淘汰 | 浏览器缓存冷了也不出 CDN；URL 即内容指纹，时代中立 |
| HTML 骨架缓存 | 仅首页 `/` 与搜索页 `/search` 的 HTML | `.cache/keep/`（磁盘） | 7 天，累计写满 5MB 整盘清 | 纯壳跨会话/跨重启命中；数据全走 XHR，过期交旧 + 后台重拉 |
| XHR 内存缓存 | github.com 全部数据响应：JSON 家族（`application/json`、`+json`、`ndjson`）、纯文本、软导航 HTML 片段 | 进程内存（不落盘） | 15 分钟 TTL，总量 5MB | 通知、计数、搜索结果、信息流、局部软导航片段全收；重启即清零，不留陈旧数据 |

**不缓存**：仓库页等整页 HTML（零转换直出）、列表/详情页的完整 HTML、头像/raw/camo/私有图、渲染域、service worker 脚本、settings/表单/登录页、非 200 响应、闸门页与截断页。

---

## 1. 三块缓存的职责边界（为什么是这个分工）

- **资产 → 磁盘**：immutable 资产的内容哈希永久有效，跨进程、跨重启复用价值极高；浏览器命中不了时由本地顶上。
- **HTML 骨架 → 磁盘**：首页/搜索页是无数据的纯框架，跨会话复用能秒出；但 GitHub 改版会让旧壳变坏，所以给 7 天保质期并配 SWR，不无限信任。
- **XHR → 内存**：全是会变的账号数据，15 分钟内高频复用（一页十几个计数/通知接口），进程退出即清零正好避免陈旧跨重启复活；不落盘也省掉个人信息写盘面。软导航 HTML 片段（`conduit`/`_filter` 等局部填充）虽是 HTML，但没有 `<html>` 根、是数据不是整页，同样归这一层。

三者键空间独立，互不失效：登录态变化只让 XHR 换键（骨架是纯壳不受影响），写操作只让骨架标过期（XHR 靠 15 分钟 TTL 自然翻篇）。

## 2. 请求进来怎么走（读写主链路）

**取**（`cache_take`）：只接 github.com 的 GET，且请求没带 `no-cache`（Ctrl+F5 直通）。顺序固定：

1. XHR 内存命中 → 原样回放，响应带 `x-gitport-cache: xhr`；
2. 首页/搜索页骨架磁盘命中 → 回放，带 `x-gitport-cache: hit`；若条目已过期，照交旧壳并后台重拉；
3. 都没中 → 走上游；其他页面路径直接走上游。

githubassets 的资产不走这条链：它在 mitm 入口被强绑定分支接管（见第 3 节）。

**存**（`cache_put`）：先按 Host 分流——资产 host 收体投资产库；github.com 只收 200，再按路径、导航形态与 `Content-Type` 分类：

- 首页/搜索页路径 + 文档导航（`sec-fetch-dest=document`）+ `text/html` → keep 骨架（磁盘）；
- 任意路径 + 数据正文（`application/json`、`+json` 家族如 `vnd.github+json`、`x-ndjson`、`text/plain`）→ XHR（内存），**不枚举路径前缀**，新接口自动覆盖；
- 非文档导航 + `text/html` + 解压后无 `<html>` 根 + 256KB 内 → 软导航 HTML 片段，走 XHR（内存）；声称片段却是整页或超限则原样交回、不收；
- 其余（图片、二进制、整页 HTML）→ 原样透传，不缓存。

首页/搜索页路径上的 JSON 是数据不是壳，改道 XHR（不再被 keep 吞掉）；骨架取侧变体固定 `-html`，与存侧写键一致。

写盘类任务投给单个串行管家线程（有界队列 64，满了就丢弃，缓存是 best-effort），主路径不等磁盘；XHR 入库是纯内存操作，直接在请求线程完成。

## 3. 资产库（磁盘，`.cache/assets/`）

- **键**：完整 URL（含查询串）。取侧用条目里记的 key 与请求 URL 精确比对，对不上就是 miss——永不跨发版给错内容。
- **收录门**：200 + `Content-Type` 含 javascript / css / font；其余透传。响应头原样带回，包括 GitHub 的一年 immutable 头。
- **落盘槽位**：按"资产名"寻址（文件名去掉内容哈希；JS 的 `-哈希`、CSS module 的 `.16位hex.module` 两族），同一资产的新哈希覆盖旧条目——库里不会堆积旧代。文件名本身是 URL/资产名的 FNV-1a 摘要。
- **写入格式**：`[4B 头长][头 JSON：key/status/headers][体]`，先写 `tmp/` 再原子 rename，永远存不出半帧；`Set-Cookie` 从缓存元数据剔除（浏览器响应本身不动）。
- **容量**：20MB 上限（2026-11-25 从 15MB 提升：GitHub 单页资产常超 15MB，热资产被年龄驱逐会导致反复回源）。超限按 mtime 从旧到新删，删到限额内；误淘汰无害，下次请求重拉后时间戳变新自动排最后。
- **miss 路径**：`serve_or_fetch` 强绑定——本地命中即回放；miss 登记等待者，首个请求发起**与浏览器连接解耦**的独立拉取，同 URL 并发只拉一次，后来者等同一份结果。头/体各有 30 秒停滞界（装死判失败），但**不设总时限**，慢滴流拉多久都行。任务无论成功/失败/panic 都必须唤醒等待者，否则同 URL 会永久楔死；拉取失败回落既有转发路径。

## 4. HTML 骨架缓存（磁盘，`.cache/keep/`）

- **收录范围**：只有 `/` 和 `/search`。列表页、仓库页、详情页一律不进——它们带服务端渲染的数据，存下来就是陈旧数据；仓库页更不能碰（见第 9 节）。
- **键**：`GET + host + 路径查询串 + 变体 + 编码标签 + -k`，**不含会话号、不含身份标签**。骨架是纯壳，跨登录、跨会话、跨重启共用。搜索页查询串**必须保留**（结果虽走 XHR，但骨架形态与查询有关，剥掉会串结果）：只做 `p=1` 补齐与参数排序归一化。取侧按 `Accept` 猜 `-html`/`-json` 变体，猜错只是 miss。编码分 br/gzip/identity 三桶。
- **保质期**：7 天按文件 mtime 判定；取不到时间（含时钟回拨导致 mtime 在未来）保守按过期处理。
- **SWR（交旧 + 后台重拉）**：过期条目不判死——旧壳照常交付，同时去重后起后台任务带 cookie 重拉；失败 60 秒再试，直到成功、确认上游 404/410（删条目）、或确认会话已死（停止，旧壳继续）。新壳覆盖后 mtime 复新，过期标记自动解除。前台零等待。
- **写后失效**：写操作成功后对 keep 条目**不删，只把 mtime 拨到保质期外**（`mark_entry_expired`）。下次命中自然走上面的 SWR 交旧重拉，不需要任何额外状态位。
- **容量**：5MB 是**累计写入量**计数（`BYTES_SINCE_WIPE`），攒够就整盘清空 `keep/` 和 `tmp/`，不做淘汰排序——骨架可再生，简单胜过精确。约百余份骨架。
- **落盘门检**（写入前全部通过才存）：单条正文 ≤ 2MB、无 `no-store`、HTML 完整（末尾 2KB 有 `</html>`）、带会话却拿到未登录页不存、闸门页不存、搜索限流降级骨架不存。判定前先解压（主站正文恒 gzip/br，不解压等于裸奔）。
- **读侧自愈**：截断骨架读时删文件当 miss；未登录页/闸门页读时不认命中。
- **写入异步**：嗅探读走的前几帧要拼回去，否则存半页；`Bytes` 引用计数浅克隆跨线程零拷贝；管家线程串行落盘，每条消息独立 panic 护栏。

## 5. XHR 内存缓存（进程内存，不落盘）

- **收录门**：github.com 的 GET、200，正文属于以下任一类（类型判定大小写不敏感）：
  - 数据正文：`application/json`、`application/*+json`（`vnd.github+json`、`problem+json`、`graphql-response+json` 等）、`*ndjson`、`text/plain`；
  - 软导航 HTML 片段：请求 `sec-fetch-dest` 不是 `document`（无该头按整页处理，保守不收）+ `text/html` + 解压后无 `<html`/`<!doctype` 根 + 256KB 内。无根检查在收体后做，声称片段却是整页或超限的原样交回、不收。
  - 首页/搜索页路径的 JSON 也归这一层（改道自 keep，因为它是数据不是壳）。
  - **不限路径**：dashboard、通知、计数、搜索结果、信息流、`conduit`/`_filter` 局部片段等全部自动覆盖，不维护前缀白名单。Ctrl+F5 带 `no-cache` 直通。
- **键**：`GET + host + 路径 + 查询串原样 + 身份标签 + 编码标签`。身份标签：未登录 `-cloggedout`，登录为 `user_session` 值的稳定摘要（`-cs…`）——不用账号名（客户端自报可伪造），不用轮换 cookie（否则每次轮换都换键）；Cookie 被 h2 拆成多行时要全拼再找 `user_session`。
- **TTL**：15 分钟，用 `Instant` 判定（不受系统时钟回拨影响）。命中时若已过期，惰性删除当 miss；写入时顺带批量清扫过期条目，没有后台定时器。
- **容量**：总量 5MB，超限时按**过期时间最早**先淘汰（即将到期的先腾位），删到限额内；**没有单条大小上限**——大 JSON 也可以存，只要总量不超。同键覆盖先扣旧账再加新账。
- **回放**：元数据里的 `Set-Cookie` 在入库时剔除（避免回灌旧 cookie），响应头与体原样回放，带 `x-gitport-cache: xhr` 标记；全部 XHR 的命中/入库日志按路径去重限流，避免刷屏。
- **进程语义**：重启即清零——这是刻意的，账号数据不跨进程留存。

## 6. 键与身份小结

| 层 | 身份标签 | 会话号 | 编码 | 查询串 |
| --- | --- | --- | --- | --- |
| 资产库 | 无（键就是 URL） | 无 | 含在 URL/头里 | 原样 |
| keep 骨架 | 无（纯壳跨登录） | 无 | br/gz/id 分桶 | 搜索页归一化（保留并补 `p=1`） |
| XHR | 有（`user_session` 摘要 / 未登录固定值） | 无 | br/gz/id 分桶 | 原样 |

一个账号换登录态：XHR 全 miss 一次，骨架与资产照常命中，不会串账号数据。

## 7. 目录、ACL 与原子写

统一根在 `exe_dir/.cache/`：`assets/`（资产）、`keep/`（骨架）、`tmp/`（原子写中转）。首次触达目录时用 Windows 原生 API 套 DACL：仅当前用户与 SYSTEM 完全控制，目录 ACE 带 `(OI)(CI)` 继承标志，子文件/子目录自动继承（页面含个人信息）。继承标志必须放在 `grfInheritance` 字段——放错到权限掩码会让子目录继承出空 DACL，缓存写盘全部 `os error 5`。测试用 `icacls` 读回验证继承结果；全程无子进程。

## 8. 容量与生命周期总表

| 层 | 落盘 | 寿命 | 消亡方式 |
| --- | --- | --- | --- |
| 资产库 | `.cache/assets/` | 20MB 容量 | 超限按 mtime 从旧到新淘汰；同资产新哈希覆盖旧条目 |
| HTML 骨架 | `.cache/keep/` | 7 天 mtime | 超期交旧+后台重拉 / 写失效标过期 / 截断自愈 / 累计写满 5MB 整盘清 |
| XHR | 仅内存 | 15 分钟 | 惰性删除 / 写时清扫 / 总量超 5MB 按最早过期淘汰 / 进程退出归零 |

## 9. 日志判读表

| 日志 | 含义 | 健康判读 |
| --- | --- | --- |
| `[资产] 命中 xxx` | 浏览器缓存冷时的本地回放 | 偶发正常 |
| `[资产] 入库 xxx` / `独立拉取入库` | 新资产首次拉取或后台补库 | 热身后消失 |
| `[缓存] 命中 ... 本地` | 首页/搜索页骨架磁盘命中 | 正常，每条路径只记一次 |
| `[缓存] XHR 回放 ...` / `XHR 入库 ...` | 内存缓存命中/写入 | 正常，限流输出 |
| `[缓存] 页面快照过期, 交旧 + 后台重拉` | SWR 生效 | 旧壳继续用，新壳随后覆盖 |
| `[缓存] 写后失效 ... keep 快照标过期` | 写操作后骨架走 SWR | 正常 |
| `[缓存] 命中失败 ... (原因)` | 盘上有条目却被读侧拒绝 | 需排查（会话死/闸门/截断） |
| `[缓存] 拒存 ... (原因)` | 搜索骨架被门检拦下 | 看原因是否预期（限流/闸门/超限） |
| `200 OK (direct)` | 仓库页零转换直出 | 成功态，不是"缓存没工作" |

## 10. 为什么是这个形状（两代失败的教训）

**第一代（html 快照 + 全局底稿 + 增量解码）**：页面碎片被当快照写入 → 解码失败 → 自愈时连全局底稿一起删 → 底稿被碎片重建 → 所有存量解码错位 → 连环自毁。根因：把"会变的数据"存了下来。

**第二代（骨架胚 + 位置换装）**：不存数据了，改冻结资产引用、发版日换回旧引用——但内容哈希变了就意味着**内容真的变了**，旧 JS 配新 payload = 白屏（实测 2026-11-17 02:13，30/102 混装三代直接复现）。根因：JS 与数据是同代耦合的，冻结任何一代都会错配。

**现在（零转换 + 资产库 + 纯壳骨架 + 短命 XHR）**：仓库页 HTML 一个字节不改；磁盘里只有"永不变"的资产和"无数据"的纯壳；会变的账号数据只活 15 分钟且只在本进程内存里。缓存层里不再有需要跨版本对齐的东西，所以不再有能白屏的缓存。

## 11. 边界与已知限制（诚实清单）

- 浏览器缓存命中时代理侧看不到请求，日志空是正常态，不要据此判断资产库失效。
- 头像 / raw / camo / 私有图、渲染域、service worker 脚本不收，保持直连。
- Range 请求不走资产库（只收完整 GET）。
- XHR 15 分钟是固定 TTL，不读上游 `Cache-Control`；写操作后 XHR 不主动失效，靠 TTL 翻篇。
- 搜索骨架取侧仍按 `Accept` 猜 `-html`/`-json` 变体，猜错只是 miss；首页取侧变体固定 `-html`，与存侧写键一致（曾因取侧用空串导致首页骨架永不命中）。首页/搜索页的 JSON 响应不进 keep，数据由 XHR 层负责。
- SSE（`text/event-stream`）不收：响应体不结束、事件流有游标语义，无法按"完整响应"缓存；WebSocket 长连接走转发，不进任何缓存层。
- 软导航片段靠"非 document 导航 + 无 html 根 + 256KB 内"三重门检识别；上游若把片段包成完整 HTML（带根）则不收，宁可漏存不误存整页。
- 5MB 骨架清盘按累计写入量触发，不是精确目录统计；清盘后下轮访问重建，无害。
- 登录态切换 = XHR 身份标签变 = 内存缓存全 miss 一次（骨架与资产不受影响）。
- GitHub 发版日：新哈希资产有一波一次性拉取——这是新 JS 配新数据的必要成本。
