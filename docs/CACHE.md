# 缓存体系全解

不谈实现，只谈机制：每一层存什么、不存什么、活多久、死掉怎么办、坏了长什么样。

---

## 0. 一句话总览

缓存只有**两层**，且互不依赖：

| 层 | 管什么 | 一句话 |
| --- | --- | --- |
| 浏览器缓存 | 请求都不发 | 资产带一年 immutable 头，浏览器收下后连代理都不问 |
| 资产库 | 发了请求也不出 CDN | githubassets 的 js/css/字体按 URL 一存永逸，本地回放 |

页面 html **一律不缓存**：仓库页/首页/列表页/搜索页的 html 每次真拉真交付——html 是数据本身，会变的东西不存。这个决定是三条教训换来的（见第 12 节）。

---

## 1. 什么进缓存、什么永远不进

| 内容 | 处理 | 寿命 | 理由 |
| --- | --- | --- | --- |
| 仓库页 html（`/<owner>/<repo>/`） | 零转换直出 | 不存 | 数据必须永远新鲜；且页面的 JS 与数据是同代耦合的，任何"存 html"都会造成版本错配 |
| 首页骨架（`/`） | 跨会话缓存 | 7 天 | 纯框架页，数据全靠 XHR |
| 列表页（issues/pulls/commits 等） | 会话缓存 | 空闲 15 分钟清盘 | 同会话内反复翻看，值得存 |
| 搜索页与搜索计数 XHR | 会话缓存 | 同上 | 同上 |
| 首页信息流片段（/conduit/* 等软导航响应） | 会话缓存 | 同上 | 不是完整页面，只做会话级短存 |
| githubassets 的 js/css/字体 | 资产库 | 200MB 整库清空 | 全站共享、内容哈希命名、immutable |
| 头像 / raw / camo / 私有图 | 透传直连 | — | 内容与人/仓库绑定，无复用价值 |
| 文档站（viewscreen） | 透传直连 | — | 独立域，自有缓存头 |
| service worker 脚本（assets-cdn/worker） | 透传直连 | — | 量小，浏览器自缓存（用户决议） |
| settings、表单、登录页 | 永不缓存 | — | 防伪 token 与个人状态 |
| 非 200、未登录页、闸门页、截断页 | 拒收 | — | 见门检一节 |

---

## 2. 键：什么算"同一个页面"

键 = 方法 + 域名 + 路径 + 查询串 + 身份标签 + 编码标签（跨会话层再叠会话号）。每一截都在防一种串页事故：

- **路径归一**：搜索页无页码补 `p=1`、参数按名排序（写法不同算同一页）；其余路径一个字符不动（参数顺序可能有语义）
- **身份标签**：未登录固定一枚；登录 = `user_session` 值的摘要。不用账号名（客户端自报可伪造）、不用轮换 cookie（否则每个请求一个新键）。同机两个账号不串页，`user_session` 轮换只损失一次命中
- **编码标签**：brotli/gzip/identity 三桶分键——给谁协商了什么编码就存什么编码，br 字节绝不发给只要 gzip 的人
- **会话号**：会话页键带会话号，旧会话条目自然失联；首页骨架等跨会话层不带

---

## 3. 会话生命周期

- 空闲 **15 分钟** → 下一次导航触发整盘清空（只清会话层；骨架层与资产库不受牵连）
- 15 分钟内连续浏览 → 会话延续
- 进程第一页也算新会话（上一次进程的残留不可信）
- 时钟被回拨 → 年龄一律按"已过期"保守处理

---

## 4. 资产库（核心）

- 键 = 完整 URL；收录门：200 + js/css/字体 + ≤2MB；其余透传
- 命中顺序：浏览器缓存（多数请求到不了代理）→ 资产库 → CDN（顺手入库）
- 回放：响应头原样带回，**包括 GitHub 的一年 immutable 头**——浏览器缓存住之后，后续页面连代理都不问。热身后看不到 `[资产] 命中` 行是正常，那说明浏览器在替你命中
- 全站共享：首页、搜索、所有仓库页、gist——同一套键（键是 URL，与页面无关）
- **时代中立**：URL 里的哈希就是内容指纹，同 URL 永远同字节。GitHub 发版换哈希 = 新 URL = 新条目，旧条目自然闲置——**库永远不会给错内容**，这是它与"冻结引用换装"那代方案的本质区别
- 容量：200MB 攒够整库清空（资产可再生，不做逐条淘汰）

三个场景对账：

| 场景 | 没有资产库 | 有资产库 |
| --- | --- | --- |
| 平时浏览（同部署期） | 浏览器 immutable 命中，零请求 | 一样 |
| 浏览器缓存冷了（清缓存/换浏览器/淘汰） | ~100 个资产逐个翻墙拉 CDN | 全部本地秒回 |
| GitHub 发版日 | 新哈希资产逐个拉，一次 | 一样（新 JS 必须配新数据，这波拉取是正确行为） |

---

## 5. 仓库页：零转换直出

仓库页 html **一个字节都不改**地交付。历史上有过两代"改造 html"的尝试（快照增量、骨架换装），都死于同一个物理事实：

> GitHub 仓库页的 JS 与数据（embeddedData）是**同代耦合**的——发版日两者的接口一起变。任何"旧引用配新数据"的拼装（无论按内容哈希猜测还是按位置映射）都会让旧 JS 解析新 payload 失败 → 白屏。实测两次（2026-11-17 02:13 那次 30/102 混装三代直接复现）。

所以这一层的正确形态是**什么都不做**：html 直通，资产交给资产库。由此：

- 没有失效、没有过期、没有后台重拉——数据永远本次的
- 发版日 = 新哈希资产拉一波（正确行为），资产库收下后归零
- 页面损坏的可能性与缓存层无关（我们不碰 html）

---

## 6. 首页骨架与列表页

- 首页骨架（`/`）：跨会话存 7 天——纯框架页，数据全靠 XHR 刷新。超期不判死：交旧 + 后台静默重拉（60s 重试直到成功或页面确认不存在），覆盖入库后自动恢复
- 列表页/搜索页：会话缓存，键含会话号，翻页（React 软导航）靠路径识别入缓存
- 写操作成功 → 前缀匹配失效：命中的会话条目删除；**骨架层条目不删，标"数据过期"**（时间戳拨到保质期外——旧壳照常可交，下次命中触发后台重拉，覆盖后自动解除），全程无额外标记状态

---

## 7. 防污染门检（读侧与写侧双道）

- **未登录页防收**：带着会话却拿到登录页 = 会话已死，不存也不当命中
- **闸门页防收**：2FA 验证、密码确认、限流页——GitHub 拿这些页顶替你请求的 URL，存下会一直显示，一律拒收
- **截断页自愈**：骨架条目缺结尾标记 → 当场删文件当 miss（断流的半页若活满保质期 = 必现白屏）
- **搜索骨架拦截**：限流降级页缺结果载体，不入缓存（否则一次限流被固化）
- **压缩感知**：所有体面判定先解压再扫（主站正文恒压缩，不解压的判定等于裸奔）

## 8. 日志判读表

| 日志 | 含义 | 健康判读 |
| --- | --- | --- |
| `[资产] 入库 xxx` | 新资产首次拉取 | 热身后消失 |
| `[资产] 命中 xxx` | 浏览器缓存冷时的本地回放 | 偶发正常 |
| `[缓存] 命中 ...` | 列表页/首页会话缓存 | 正常 |
| `[资产] 入库 (xxx B)` | 迷你 chunk（不足 1KB 按字节显示） | 正常 |

**注意**：仓库页访问的日志只有 `200 OK (direct)` 一行 = 零转换直出，是成功态。资产相关的行只在新资产/冷缓存时出现。

## 9. 容量与生命周期总表

| 层 | 落盘 | 寿命 | 消亡方式 |
| --- | --- | --- | --- |
| 会话条目 | `.cache/pages/` | 会话期 | 空闲 15 分钟整盘清 / 写失效删除 / 200MB 攒够清盘 |
| 首页骨架 | `.cache/keep/` | 7 天 | 超期交旧+后台重拉 / 写失效标过期 / 截断自愈 |
| 资产库 | `.cache/assets/` | 200MB | 攒够整库清空 |

## 10. 边界与已知限制（诚实清单）

- service worker 脚本（github.com 域）不收，保持直连（决议）
- 头像 / raw / camo / 私有图等内容域不收——内容与人绑定，无复用价值
- 超 2MB 的 githubassets 文件不收，直连透传；Range 请求不拦
- 资产库按 URL 存，不去重"同内容异 URL"（GitHub 内容哈希命名天然去重）
- 切换登录态 = 身份标签变 = 页面层全 miss 一次（资产层不受影响，键是 URL）
- 时钟回拨：一切年龄判定保守按"过期"处理
- GitHub 发版日：新哈希资产有一波一次性拉取——这是新 JS 配新数据的**必要成本**，任何试图消除它的缓存手段（冻结引用/换装）都会造成版本错配

---

## 11. 为什么是这个形状（两代失败的教训）

**第一代（html 快照 + 全局底稿 + 增量解码）**：页面碎片被当快照写入 → 解码失败 → 自愈时连全局底稿一起删 → 底稿被碎片重建 → 所有存量解码错位 → 连环自毁。根因：把"会变的数据"存了下来。

**第二代（骨架胚 + 位置换装）**：不存数据了，改冻结资产引用、发版日换回旧引用——但内容哈希变了就意味着**内容真的变了**，旧 JS 配新 payload = 白屏（实测）。根因：JS 与数据是同代耦合的，冻结任何一代都会错配。

**现在（零转换 + 资产库）**：html 完全不碰，资产按 URL 记忆。缓存层里不再有任何"需要跨版本对齐"的东西，所以不再有能白屏的缓存。
