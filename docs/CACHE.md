# 页面缓存（Page Cache）

> 代码唯一真相：`src/server/mitm/page_cache.rs`（判定/键位/会话/闸门/底稿+分段增量/SWR）、`src/server/mitm/redirect_memo.rs`（头像 302 记忆）。
> 本文已核对至 2026-11-16 提交 3aefffa（v6.11 行为 + 头像跳转学习范围放宽），关键条目均有单元测试钉着。

**定位一句话**：缓存分三层——资产（JS/CSS）浏览器 immutable 缓存直出（代理零参与）、页面数据走 XHR 实时直通（不缓存）、HTML 按仓库快照跨会话缓存（底稿+分段增量存储，过期交旧+后台静默重拉）。代理只管第三层。

---

## 0. 三层模型（先看这个）

| 层 | 内容 | 谁在缓存 | 为什么 |
|---|---|---|---|
| 资产（JS/CSS） | 内容哈希文件名的 chunk，**全站共享** | **浏览器 immutable 缓存**（一年） | 同 URL 永远同一字节，浏览器直出零请求；发版只换变更文件的哈希（增量） |
| 页面数据 | 文件列表/提交/侧栏/分支计数 | **不缓存，XHR 实时直通** | 数据必须实时；路由稳定不随发版换 |
| HTML（壳+初屏） | 每仓库一份（96% 全站骨架 + ~12KB 身份数据） | **代理按仓库快照**（底稿+分段增量） | 身份烧在字节里（SEO），每仓库不同；快照让回访秒开、发版隐身 |

v6.9 实测依据：48 分钟 132 个资产请求缓存命中 0 次（没变的 URL 浏览器自己消化，换哈希的代理也没见过）——资产缓存机制与开关已物理删除（要找回翻 git 历史）。同轮实测推翻了"入口大包被 GitHub 拆除"的猜测：大包只是被浏览器缓存住了（注入件交付后浏览器 immutable 直出），GitHub 是否改架构未能证实，不写进文档当结论。

## 1. 一次请求怎么走

浏览器发来 `GET github.com/...` 后，按顺序过五关：

```
① 遥测拦截   Datadog RUM / 心跳 → 本地 204，与缓存无关
② 准入判定   是不是「该缓的五类」之一？不是 → 原样回源（见 §2）
③ 查键       键命中 → 本地秒回；未命中 → 回源（键规则见 §4）
④ 闸门       回源成功后过四道门，全过才落盘（见 §5）
⑤ 学习       头像入口的跳转（301/302/307/308）顺手记一笔（见 §6）
```

命中时日志为 `[缓存] 命中 <路径> (大小 本地)`，如 `(3KB 本地)`；命中失败与拒存也会落原因（见 §7）。

## 2. 缓什么：五类准入

总前提：`host == github.com && GET && 请求不带 no-cache`（Ctrl+F5 强制回源；F5 会读缓存）。

| # | 类别 | 判定 | 键尾 | 存放 | 寿命 |
|---|---|---|---|---|---|
| 1 | 首页骨架 | path `/` | `-k` | `keep/` | 跨会话，7 天 |
| 2 | **仓库页快照**（v6.11） | 两段路径（`/owner/repo`，尾斜杠归一），排除 `/settings/*`；仅文档导航 | `-rk` | `keep/` | 跨会话，7 天 |
| 3 | 搜索列表 | path `/search`，文档导航与软导航均可 | `-s{epoch}` | `pages/` | 会话级 |
| 4 | 跟班 XHR | 固定前缀清单（`/search/count`、`/dashboard/` 等） | `-s{epoch}` | `pages/` | 会话级 |
| 5 | 其他列表页 | 末段命中 `issues / pulls / commits / releases / ...`；仅文档导航 | `-s{epoch}` | `pages/` | 会话级 |

两条细则：末段是**纯数字**当详情页，不缓存；`new`/`edit` 表单不缓存。`/settings/*` 保持会话键（账号敏感页，两段路径会被仓库页启发式误中，v6.11 测试钉住）。

**硬性排除**：非 `github.com` 的任何域名；**资产（githubassets JS/CSS）一律直连不缓存**；数据 XHR 不缓存；POST 响应（只做失效）；未登录页与闸门页。

## 3. 缓多久：会话、跨会话与 SWR

| 存放 | 生命周期 |
|---|---|
| `pages/`（会话级，上表 3/4/5） | 导航间隔超过 **15 分钟**，或**进程重启**后的第一次文档导航，整盘清空 |
| `keep/`（首页骨架 `-k`、仓库页快照 `-rk`） | 跨会话跨重启；满 **7 天**过期 |

**过期不判死（SWR）**：满 7 天的快照**照常交旧**（浏览器缓存直出，秒开），同时后台**带 cookie 静默重拉**最新壳——单流、失败 60 秒后再试、代理在跑就永不放弃；200+`</html>` 完整+会话存活三道门全过才覆盖，任一失败旧壳继续。**前台全程零感知**——包括发版边界（旧壳引用旧哈希，浏览器手里全有）。

数据新鲜度不受 SWR 影响：页面数据走 XHR 实时直通（见第 2 层），壳的年龄只影响外观版本。

## 4. 键怎么定：归一化 + 分键 + 会话号

键的骨架：`GET <host><path>?<query> + 身份标签 + 压缩标签 + 键尾`。键尾三种：

| 键尾 | 谁 | 语义 |
|---|---|---|
| `-k` | 首页骨架 | 跨会话，不带会话号 |
| `-rk` | 仓库页快照 | 跨会话，不带会话号（v6.11） |
| `-s{epoch}` | 其余（搜索/列表/跟班） | 会话号隔离，重启/换会话自然失效 |

其中两条规则只作用于 `/search`：

**归一化**——先于一切键计算：

- 去掉 `p=1`：与无 `p` 同页（GitHub 翻页链接两种形态都有，实测曾同时躺两个重复条目）
- 参数按键名排序：防将来重排
- 仅 `/search` 生效；其他路径的查询串一个字符不动（个别接口参数顺序有语义）

**分钥匙**——GitHub 搜索页按请求 `Accept` 协商出两种正文：`application/json` 回 JSON（React 软导航取数，~5KB），否则回 HTML 整页（~170-270KB）。同 URL 不同物，键尾带 `-html` / `-json`：

- 存侧以实际 Content-Type 定变体
- 取侧按请求 Accept 预测——预测错只是 miss 重取，不会把 JSON 塞给导航、把 HTML 塞给取数器

## 5. 什么进不了缓存：回源后的四道门

回源 200 之后，正文按顺序过四道门，**任一不通过即拒存**（正文照常交付浏览器，只是不落盘）：

| 门 | 拦什么 | 为什么存在 |
|---|---|---|
| 类型门 | 列表页只收 `text/html`；跟班 XHR 放宽到 JSON/纯文本；搜索页另收 JSON（软导航取数） | 不把非页面正文当页面存 |
| 未登录门 | 带会话却拿到未登录页 | 会话已死的信号，存了会顶替真页面 |
| 闸门页门 | 登录墙/限流页等已知标记 | 这类页面每次都该是新的 |
| 骨架门 | `/search` 页缺 `react-app.embeddedData`（结果数据载体） | GitHub blackbird 限流降级骨架；三态实测：正常页有载体、真实零结果页**也有**（不误杀）、降级骨架没有 |

骨架不存的后果是良性的：刷新回源，配额恢复即自愈——不拦的话一次性降级会被缓存钉成"一直坏"。

分段快照（-rk）的读侧门检跑在**还原后的明文**上：会话死亡/闸门页 → 拒绝本次命中、条目保留；不完整（缺 `</html>`）→ 连底稿一起清掉，下次全部重建（自愈）。

## 6. 头像入口 302 记忆（独立子系统）

`github.com/<user>.png?size=N` 是 GitHub 设计的重定向入口（302 为主，偶见 301/307/308）+ no-cache：浏览器每次渲染页面都必须重问一遍跳转（260-310ms × 十几个并行）。这是列表/翻页后内容"逐渐蹦出来"的最大一块。

代理记住跳转目标，同入口再问时**本地直答 302**：

- 浏览器行为不变——照样跟随跳转、照样用本地缓存的真图，只是那个来回归零
- 学习的状态码：上游回 301 / 302 / 307 / 308 都记（CDN 换域或缓存策略变化时不只有 302）；落点仍严格限头像域，登录跳转和风控页不记，命中本地一律直答 302
- 形态限定：github.com 单段 `.png` 路径（大小写不敏感）；非 github.com / 非 `.png` / 两段路径不记不答
- 上限 4096 条，超限整表重来；TTL 6 小时——用户换头像后入口 URL 不变（版本号在跳转目标里），靠过期重学把旧图窗口限在几小时内
- 学习点只有一处：`get_direct` 成功路径，新拨与复用都经过它（`mitm/mod.rs`，与两条分支各自上报改为共用一处）
- fast path 无日志；响应带 `x-gitport-route: 302memo` 便于 devtools 核对

## 7. 日志怎么读

| 日志 | 含义 |
|---|---|
| `[请求] <域名><路径> -> <状态> (<科室>)` | **每个请求一行**（v6.11 新增）：复用连接上的单个请求从此可见，科室 = cache/302memo/direct-split/dns/direct/stream/mirror |
| `[缓存] 命中 <路径> (大小 本地)` | 本地秒回，零上游，如 `(3KB 本地)` |
| `[缓存] 页面快照过期, 交旧 + 后台重拉 <路径>` | 7 天到期：旧壳秒出 + 后台静默更新换代 |
| `[缓存] 页面重拉完成, 快照已更新 (尝试 N 次)` | 后台重拉成功，下次访问即新版 |
| `[缓存] 页面重拉…失败…旧壳继续` | 后台重拉失败不碍事，旧壳继续服务 |
| `[缓存] 拒存 <路径> (原因)` | 回源成功但没落盘；原因 = 非准入 / 上游状态 / 超限 / 未登录页 / 闸门页 / 限流骨架 / 正文类型不符 / 收集失败 |
| `[缓存] 命中失败 <路径> (原因)` | 盘上有条目却被读侧拒绝（截断/碰撞/会话已死），当 miss 自愈 |
| （静默） | 上游 304：浏览器条件请求命中校验器、拿自己本地副本渲染，属正常路径，不落日志 |

## 8. 容量上限与诊断头

| 上限 | 值 | 语义 |
|---|---|---|
| 累计写量 | 200 MiB | 是「自上次清盘以来累计写入字节」的计数器，越线就整盘清空；不是磁盘实际占用上限 |
| 单条 body | 2 MiB | 回源正文超过就不落盘，正文照常交给浏览器 |
| 写队列 | 64 条 | 后台落盘用同步队列，满了直接丢这次写，不阻塞请求 |

响应带 `x-gitport-route` 供 devtools 核对走法，取值：

| 取值 | 含义 |
|---|---|
| `cache` | 页面缓存命中（另带 `x-gitport-cache: hit`） |
| `302memo` | 头像 302 记忆直答 |
| `direct-split` | README 大图纯直连多段 |
| `direct` / `mirror` | 直连 / 镜像链（镜像链缺省值） |
| `dns` | 系统 DNS 兜底腿 |
| `stream` | 流式直通 |

这些值由 `src/server/mitm/mod.rs` 统一写入响应头；缓存命中与 302 记忆的赋值在解密请求入口，其余在各自路径回传时标注。
