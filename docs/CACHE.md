# 缓存体系全解

不谈实现，只谈机制：每一层存什么、不存什么、活多久、死掉怎么办、坏了长什么样。

---

## 0. 一句话总览

三层缓存各管一段，互为乘数：

| 层 | 管什么 | 一句话 |
| --- | --- | --- |
| 浏览器缓存 | 请求都不发 | 资产带一年 immutable 头，浏览器收下后连代理都不问 |
| 资产库 | 发了请求也不出 CDN | githubassets 的 js/css/字体按 URL 一存永逸，本地回放 |
| 骨架胚 | 资产地址永不换 | GitHub 发版换哈希，交付前把引用换回冻结旧地址 |

页面 html 分两类：**仓库页永不缓存**（每次真拉真交付，数据没有"过期"概念）；**列表页/搜索/首页**按会话短存。

---

## 1. 什么进缓存、什么永远不进

| 内容 | 处理 | 寿命 | 理由 |
| --- | --- | --- | --- |
| 仓库页 html（`/<owner>/<repo>/`） | 真拉 + 抽骨架 + 换装交付 | 不存 | 数据必须永远新鲜；会变的东西不存 |
| 列表页（issues/pulls/commits 等） | 会话缓存 | 空闲 15 分钟清盘 | 同会话内反复翻看，值得存 |
| 搜索页与搜索计数 XHR | 会话缓存 | 同上 | 同上 |
| 首页信息流片段（/conduit/* 等软导航响应） | 会话缓存 | 同上 | 不是完整页面，不进仓库胚管线 |
| 首页骨架（`/`） | 跨会话缓存 | 7 天 | 纯框架页，数据全靠 XHR |
| githubassets 的 js/css/字体 | 资产库 | 200MB 整库清空 | 全站共享、内容哈希命名、immutable |
| 头像 / raw / camo / 私有图 | 透传直连 | — | 内容与人/仓库绑定，无复用价值 |
| 文档站（viewscreen） | 透传直连 | — | 独立域，自有缓存头 |
| service worker 脚本（assets-cdn/worker） | 透传直连 | — | 量小，浏览器自缓存（用户决议） |
| settings、表单、登录页 | 永不缓存 | — | 防伪 token 与个人状态 |
| 非 200、未登录页、闸门页、截断页 | 拒收 | — | 见门检一节 |

---

## 2. 键：什么算"同一个页面"

键 = 方法 + 域名 + 路径 + 查询串 + 身份标签 + 编码标签（跨会话层再叠会话号）。每一截都在防一种串页事故：

- **路径归一**：仓库页补尾斜杠（`/o/r` 与 `/o/r/` 同键）；搜索页无页码补 `p=1`、参数按名排序（写法不同算同一页）；其余路径一个字符不动（参数顺序可能有语义）
- **身份标签**：未登录固定一枚；登录 = `user_session` 值的摘要。不用账号名（客户端自报可伪造）、不用轮换 cookie（否则每个请求一个新键）。同机两个账号不串页，`user_session` 轮换只损失一次命中
- **编码标签**：brotli/gzip/identity 三桶分键——给谁协商了什么编码就存什么编码，br 字节绝不发给只要 gzip 的人
- **会话号**：会话页键带会话号，旧会话条目自然失联；首页骨架等跨会话层不带

---

## 3. 会话生命周期

- 空闲 **15 分钟** → 下一次导航触发整盘清空（只清会话层；骨架层与资产库不受牵连）
- 15 分钟内连续浏览 → 会话延续
- 进程第一页也算新会话（上一次进程的残留不可信）
- 时钟被回拨 → 年龄一律按"已过期"保守处理

---

## 4. 仓库页管线（核心）

每次进仓库页，按顺序发生五件事：

1. **真拉 GitHub**（带登录态）。没有过期判定、没有失效标记、没有后台重拉——数据永远来自这一次拉取
2. **完整文档闸**：没有结尾标记的响应（首页信息流等软导航片段）不碰胚，原样直出——片段的形状与整页不同，混进胚会让骨架反复换形
3. **抽骨架**：扫描全文中"属性值形态的 githubassets 引用"，按文档顺序得一张引用清单（实测 ~100 条）；同时取 importmap 内容的指纹。抽取前把所有 script 体按原长度置换成空格——数据区里出现的资产 URL 字符串不会混进清单，且置换不改偏移，换装直接在原文上进行
4. **比对胚**：
   - 胚不存在 / 超 7 天 / importmap 指纹变 / 引用条数变 → **换胚**，本次直出（下次起生效）
   - 引用完全一致（同部署，绝大多数访问）→ 原样直出，一个字节不改
   - 只有条数一致但哈希不同（**GitHub 发版了**）→ **换装**：按位置把新引用换回冻结旧引用
5. **交付**：identity 桶交明文，其余统一重压 gzip；nonce、CSP、标题、数据区全部来自本次真拉，与换装无关
6. **降级**：任何一步失败 → 原样直出 + 一行 `[解析] 失败` 日志

**为什么位置映射可靠**：同一页面模板的资产引用顺序是模板决定的，第 i 个对第 i 个，不需要猜测"这两个文件名是不是同一个资产"。

**为什么只冻结外链引用**：CSP 的 sha256 钉的是内联脚本内容，外链引用只约束域名——冻结外链引用，CSP、水合、nonce 全部零副作用。这就是胚从"整页壳"缩到"资产骨架"的原因： body 是 SSR 的仓库内容（文件列表、README 都在 html 里），冻它会背上旧内容闪现和水合错配；只冻资产引用，这些风险结构性消失。

---

## 5. 骨架胚

- 全局**唯一一份**，与具体仓库无关——哪一页先立胚就是哪一页的形状
- **换胚触发器**：首次 / 超 7 天 / importmap 指纹变（react 等基础库换代）/ 引用条数变（页面形状自校正）
- **剔胚自愈**：某条冻结引用被上游判死（404/410）→ 立即剔胚 → 下次访问按新骨架重剥
- 原子覆盖：永远存不出半截胚；只有解析管线能写它，没有别的写入路径
- 判读：`立胚` 行偶发 = 形状自校正，正常；**每次访问都立胚 = 形状持续漂移**，报修

---

## 6. 资产库

- 键 = 完整 URL；收录门：200 + js/css/字体 + ≤2MB；其余透传
- 命中顺序：浏览器缓存（多数请求到不了代理）→ 资产库 → CDN（顺手入库）
- 回放：响应头原样带回，**包括 GitHub 的一年 immutable 头**——浏览器缓存住之后，后续页面连代理都不问。所以热身后看不到 `[资产] 命中` 行是正常，那说明浏览器在替你命中
- 全站共享：首页、搜索、所有仓库页同一套键（键是 URL，与页面无关）
- 容量：200MB 攒够整库清空（资产可再生，不做逐条淘汰）
- 联动：资产被上游判死 = 冻结引用已死 = 剔胚

---

## 7. 失效与写后处理

- **写操作成功**（POST/PUT/DELETE/PATCH 返回成功或跳转）→ 前缀匹配失效：写路径与其父路径命中的**会话条目删除**
- **骨架层条目不删，标"数据过期"**：文件时间戳拨到保质期外——旧壳照常可交，下次命中自动触发后台静默重拉，覆盖入库后时间戳复新、标记自动解除。全程不依赖额外的标记状态
- **仓库页**：无失效概念（html 永不缓存，数据永远本次的）
- **上游确认页面已死**（404/410）：条目删除 / 胚剔除，下次访问直连见真实 404；上游误报则直连重建，自愈

---

## 8. 防污染门检（读侧与写侧双道）

- **未登录页防收**：带着会话却拿到登录页 = 会话已死，不存也不当命中
- **闸门页防收**：2FA 验证、密码确认、限流页——GitHub 拿这些页顶替你请求的 URL，存下会一直显示，一律拒收
- **截断页自愈**：骨架条目缺结尾标记 → 当场删文件当 miss（断流的半页若活满保质期 = 必现白屏）
- **搜索骨架拦截**：限流降级页缺结果载体，不入缓存（否则一次限流被固化）
- **压缩感知**：所有体面判定先解压再扫（主站正文恒压缩，不解压的判定等于裸奔）

---

## 9. 失败与降级链（永不白屏原则）

仓库页管线每一步的失败出路：

| 失败点 | 出路 |
| --- | --- |
| 正文非 UTF-8 / 抽不到引用 / 换装结构不符 | 原样直出 + `[解析] 失败` 日志 |
| 冻结引用被上游判死 | 剔胚，下次重剥 |
| 换装后浏览器缺某个旧资产 | 资产库回放；库也没有 → 拉 CDN 顺手入库 |
| 上游拉取本身失败 | 照常报错（该失败与缓存无关） |

原则：**解析失败 = 加速暂时消失，不是页面损坏**。GitHub 怎么改，最坏后果都是"回到无加速状态 + 日志叫一声"。

## 10. 日志判读表

| 日志 | 含义 | 健康判读 |
| --- | --- | --- |
| `[解析] 立胚 N 条 (首次)` | 冷启动 | 正常 |
| `[解析] 立胚 N 条 (结构变化/importmap变更)` | 形状/模块图自校正 | 偶发正常；**每次访问都出现 = 报修** |
| `[解析] 立胚 N 条 (超期)` | 7 天到期换代 | 正常，7 天一次 |
| `[解析] 资产引用换旧 N 处 (GitHub 已发版)` | 发版日换装 | 正常，发版日出现 |
| `[解析] 失败 ... 直出` | GitHub 改版信号 | **需要改解析规则的唯一信号** |
| `[解析] 片段不立胚 ... 直出` | 软导航片段被完整文档闸拦下 | 按路径首见一条，正常 |
| `[资产] 入库 xxx` | 新资产首次拉取 | 热身后消失 |
| `[资产] 命中 xxx` | 浏览器缓存冷时的本地回放 | 偶发正常 |
| `[资产] 上游 404 ... 胚失效` | 冻结引用被上游判死 | 自愈动作，联动重剥 |
| `[缓存] 命中 ...` | 列表页/首页会话缓存 | 与仓库页管线无关 |

**注意**：仓库页访问的日志安静（无 `[解析]`/`[资产]` 行）= 合成跑完且结论"零差异"，是成功态不是失效态。

## 11. 容量与生命周期总表

| 层 | 落盘 | 寿命 | 消亡方式 |
| --- | --- | --- | --- |
| 会话条目 | `.cache/pages/` | 会话期 | 空闲 15 分钟整盘清 / 写失效删除 / 200MB 攒够清盘 |

| 资产库 | `.cache/assets/` | 200MB | 攒够整库清空 / 资产 404 联动剔胚 |

## 12. 边界与已知限制（诚实清单）

- service worker 脚本（github.com 域）不收，保持直连（决议）
- 头像 / raw / camo / 私有图等内容域不收——内容与人绑定，无复用价值
- 超 2MB 的 githubassets 文件不收，直连透传；Range 请求不拦
- 资产库按 URL 存，不去重"同内容异 URL"（GitHub 内容哈希命名天然去重）
- 胚与页面形状：GitHub 若按请求随机变化引用数，胚会持续重剥（信号 = 频繁立胚行）；实测同一会话内稳定
- 切换登录态 = 身份标签变 = 页面层全 miss 一次（资产层不受影响，键是 URL）
- 时钟回拨：一切年龄判定保守按"过期"处理

## 13. 为什么是这个形状

上一代机制（缓存 html 快照 + 全局底稿 + 读取时解码增量）有一条自毁反馈环：页面碎片被当快照写入 → 解码必然失败 → 失败自愈时连全局底稿一起删 → 底稿被下一块碎片重建 → 所有存量解码错位 → 再删。html 里会变的东西（数据）和不变的东西（资产地址）被存在同一个需要版本对齐的层里，任何错位都会连锁。

现在的形状把两者彻底分开：**会变的（数据）永不存**，**不变的（资产地址）冻成一份只有解析管线能写的东西**，中间不再存在需要跨版本对齐的存储。失效、过期、重拉这些概念只在"会变的"半边出现过，如今那半边根本不进缓存。
