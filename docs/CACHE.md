# 页面缓存（Page Cache）

> 代码唯一真相：`src/server/mitm/page_cache.rs`（判定/键位/会话/闸门）、`src/server/mitm/redirect_memo.rs`（头像 302 记忆）。
> 本文与 2026-10-28 的代码行为一致，关键条目均有单元测试钉着。

**定位一句话**：代理只缓存 `github.com` 的会话型列表 HTML/JSON——它们走网络慢、又是反爬敏感接口；其余一切按 GitHub 自己的缓存头交浏览器管。

---

## 1. 一次请求怎么走

浏览器发来 `GET github.com/...` 后，按顺序过五关：

```
① 遥测拦截   Datadog RUM / 心跳 → 本地 204，与缓存无关
② 准入判定   是不是「该缓的四类」之一？不是 → 原样回源（见 §2）
③ 查键       键命中 → 本地秒回；未命中 → 回源（键规则见 §4）
④ 闸门       回源成功后过四道门，全过才落盘（见 §5）
⑤ 学习       头像入口的 302 顺手记一笔（见 §6）
```

命中时日志为 `[缓存] 命中 <路径> (N 本地)`；命中失败与拒存也会落原因（见 §7）。

## 2. 缓什么：四类准入

总前提：`host == github.com && GET && 请求不带 no-cache`（Ctrl+F5 强制回源；F5 会读缓存）。

| # | 类别 | 判定 | 存放 |
|---|---|---|---|
| 1 | 首页骨架 | path `/` | `keep/`（跨会话，7 天） |
| 2 | 搜索列表 | path `/search`，文档导航与软导航均可 | `pages/` |
| 3 | 跟班 XHR | 固定前缀清单：`/search/count`、`/search/blackbird_count`、`/search/warm_blackbird_caches`、`/in-product-messaging/`、`/github-copilot/chat/repositories_search`、`/dashboard/`、`/productivity_dashboard/`、`/_filter/`、`/_side-panels/`、`/notifications/indicator`、`/cmc_internal/` | `pages/` |
| 4 | 其他列表页 | 末段命中 `issues / pulls / commits / releases / discussions / notifications / feed / trending / explore / topics / stargazers / watchers / forks / activity`，或列表词后跟**非数字**段；仅文档导航 | `pages/` |

列表页两条细则：末段是**纯数字**当详情页，不缓存（`/issues/123`）；`new`/`edit` 表单不缓存（防伪 token 可能已轮换）。

**硬性排除**（写死，不因任何开关改变）：非 `github.com` 的任何域名；仓库详情页/设置页/文件浏览；所有 POST 响应（只做失效）；未登录页与闸门页（见 §5）。

## 3. 缓多久：会话与生存期

| 存放 | 清除时机 |
|---|---|
| `pages/`（会话级，上表 2/3/4） | 导航间隔超过 **15 分钟**，或**进程重启**后的第一次文档导航，整盘清空 |
| `keep/`（首页骨架） | 只按 7 天文件寿命，清盘动不到它 |

两条细则：只有**文档导航**驱动会话寿命——跟班 XHR/轮询不续命；首页骨架存 `keep/` 所以跨会话复用。放了一晚回来第一下必现拉，是设计内行为。

## 4. 键怎么定：归一化 + 分钥匙

键的骨架：`GET <host><path>?<query> + 身份标签 + 压缩标签 + 变体 + 会话号`。其中两条规则只作用于 `/search`：

**归一化**——先于一切键计算：

- 去掉 `p=1`：与无 `p` 同页（GitHub 翻页链接两种形态都有，实测曾同时躺两个重复条目）
- 参数按键名排序：防将来重排
- 仅 `/search` 生效；其他路径的查询串一个字符不动（个别接口参数顺序有语义）

**分钥匙**——GitHub 搜索页按请求 `Accept` 协商出两种正文：`application/json` 回 JSON（React 软导航取数，~5KB），否则回 HTML 整页（~170-270KB）。同 URL 不同物，键尾带 `-html` / `-json`：

- 存侧以实际 Content-Type 定变体
- 取侧按请求 Accept 预测——预测错只是 miss 重取，不会把 JSON 塞给导航、把 HTML 塞给取数器

## 5. 什么进不了缓存：回源后的四道门

回源 200 之后，正文按顺序过四道门，**任一不通过即拒存**（正文照常交付浏览器，只是不落盘）：

| 门 | 拦什么 | 为什么存在 |
|---|---|---|
| 类型门 | 列表页只收 `text/html`；跟班 XHR 放宽到 JSON/纯文本；搜索页另收 JSON（软导航取数） | 不把非页面正文当页面存 |
| 未登录门 | 带会话却拿到未登录页 | 会话已死的信号，存了会顶替真页面 |
| 闸门页门 | 登录墙/限流页等已知标记 | 这类页面每次都该是新的 |
| 骨架门 | `/search` 页缺 `react-app.embeddedData`（结果数据载体） | GitHub blackbird 限流降级骨架；三态实测：正常页有载体、真实零结果页**也有**（不误杀）、降级骨架没有 |

骨架不存的后果是良性的：刷新回源，配额恢复即自愈——不拦的话一次性降级会被缓存钉成"一直坏"。

## 6. 头像入口 302 记忆（独立子系统）

`github.com/<user>.png?size=N` 是 GitHub 设计的「302 Found + no-cache」入口：浏览器每次渲染页面都必须重问一遍跳转（260-310ms × 十几个并行）。这是列表/翻页后内容"逐渐蹦出来"的最大一块。

代理记住跳转目标，同入口再问时**本地直答 302**：

- 浏览器行为不变——照样跟随跳转、照样用本地缓存的真图，只是那个来回归零
- 形态限定：github.com 单段 `.png` 路径（大小写不敏感）；非 github.com / 非 `.png` / 两段路径不记不答
- 上限 4096 条，超限整表重来；TTL 6 小时——用户换头像后入口 URL 不变（版本号在跳转目标里），靠过期重学把旧图窗口限在几小时内
- 学习点挂两处：拨号后分支与连接复用快路径（头像请求几乎总走复用路径）
- fast path 无日志；响应带 `x-gitport-route: 302memo` 便于 devtools 核对

## 7. 日志怎么读

| 日志 | 含义 |
|---|---|
| `[缓存] 命中 <路径> (N 本地)` | 本地秒回，零上游 |
| `[缓存] 拒存 <路径> (原因)` | 回源成功但没落盘；原因 = 非准入 / 上游状态 / 超限 / 未登录页 / 闸门页 / 限流骨架 / 正文类型不符 / 收集失败 |
| `[缓存] 命中失败 <路径> (原因)` | 盘上有条目却被读侧拒绝（截断/碰撞/会话已死），当 miss 自愈 |
| （静默） | 上游 304：浏览器条件请求命中校验器、拿自己本地副本渲染，属正常路径，不落日志 |
