# 镜像与切片统合加速

> 判定逻辑唯一真相:`src/server/mitm/mirror.rs`(派发/竞速/降权)、`merge.rs`(段合并与让位)、`direct_split.rs`(纯直连多路)。本文从上往下就是两条流量线的完整走法。

## 1. 两条流量线

| 流量线 | 入口 | 走法 |
| --- | --- | --- |
| 大文件/Release(objects、release-assets、github.com 附件路径) | master_route → Mirror | 切片竞速 → merge 合并；切片不成立时单流 ECT 直发 |
| 媒体白名单(raw、user-images、private-user-images、media、camo、gist、avatars) | switchboard → try_direct_split | 探片定段 → 单通道多段并发 → 镜像救援 |

两条线的候选都是 **镜像链 + 直连同台**：直连以 `direct/{host}` 身份参与，与镜像一视同仁；502 只在全部候选失败时发生。直连腿的拨号/游标/连接池/记账由 `mitm/mod.rs` 组装成 `DirectLeg` future 注入。

## 2. 大文件线

### 2.1 先判切片，不成立再单流

切片前提(全部满足才切):GET、非探片(bytes=N-N 是下载器探路)、总长可探(仅无 Range 分支需要探测；带 Range 的校准切片区间自给，无需探测)、且切片门=【校准(未测镜像>0 且候选全闲)或无 Range(原生浏览器下载——浏览器不会自己开并行)】。**切片门与是否带 Range 无关**(代码:`(未测镜像>0 且候选全闲) || 无 Range`,二选一即切)：带 Range 的请求(下载器自己拆好的分片连接)默认单流——并行度归下载器，ECT 挑家直发；唯一例外是冷启动校准窗口：首波第一条大段连接恰好赶上"有未测镜像且候选全闲"时，照样把**这条请求的区间**等分给全部候选(每候选一片，直连腿同权)，这一刀是给下载器做一次性测速校准的。校准机会基本只有这一次——切片一开各候选立即有在途与成绩，"未测>0 且全闲"随即破产，下载器后续波次的连接全部落回单流派发。切片不设大小门槛——第一目的是测速与给无下载器的客户端供并行。

### 2.2 总长探测(无 Range 时)

无 Range 的请求先发 `bytes=0-0` 探总长，**串行试：直连先试，再按镜像链序逐家**，第一家给出 Content-Range 总长的即用，全败回单流。总长记 10 分钟，同 URL 下一条不必再探。上游忽略 Range 回 200 → 整份按单流交付，并记"不可切"10 分钟。

### 2.3 段位分配

- 每候选一片(区间 ÷ 候选数，直连腿同权)：校准期 350ms 那次体检，全场最快段保留不切(本就满速，切下来重派反而亏)，其余段按公式只切尾部一段(C=(R−P·V)×V_fast/(V_fast+V))、留切同时完成，交给 5ms ECT 挑家重派，切成才锁死(§3)

### 2.4 段请求卫生

每段独立 GET:剥 Accept-Encoding(每段各压一遍拼回是坏数据)、剥条件头(304 对段请求无意义)、剥身份头(Cookie/Authorization/Referer/UA → 恒定浏览器 UA)。直连段跟 302 最多两跳，每跳头预算 2 秒；有镜像兜底时整段预算 4 秒，无镜像不设——唯一的路不能掐。

### 2.5 段校验

每段必须 206 且 Content-Range 起点对准刀口、终点不越界——错位 = 静默截断，按这家失败换下一个。总长对账:探得/记忆的总长与首段 206 自报不符 = 记忆陈旧(对象换版/镜像转码)→ 作废记忆回单流。

### 2.6 交付与补发(merge.rs)

交付线按偏移穿行段表(BTreeMap)，段缓冲 2MB 先到先存;停滞 5 秒零帧 → 缩边界，已收字节留下、尾巴排补发(缓冲不丢);补发按 5ms 单窗 ECT 挑家、分数含本家爬坡;连续 6 次补发空手 = 放弃。校准重分配见 §3；直连腿骑单通道，段间让位无意义不参与。

## 3. 单窗 ECT、校准期与本段判据(派发的分)

**一张窗**：每面源只有分配窗(5ms)，新连接/补发/重派共用——独立线程 5ms 一拍，零收一律沿用不清零(速率估计)。350ms 是校准期长度(段体检间隔)。Windows 定时器实际粒度 ~15ms，所有源同刻度，排名不受影响。

**派发分数** = (在途字节 + 新请求) × 5ms ÷ 上窗实收 **+ 本家爬坡毫秒**——真毫秒，最小者胜、无容差；零历史垫底(闲者先试)，爬坡项照样加。

**爬坡毫秒** = 响应头到达→首帧到达的 EMA(α=1/4)，按每家记账。同一通道每流爬坡大差不差，故切尾判据与派发都读本家这个值。镜像首切/补发、直连段都打点；单流不写(读到 0 = 无先验)。段速率也从首帧起算——爬坡不进速率分母，只在这里单独计一次。

**切片门**（代码语义:`(未测镜像>0 且候选全闲) || 无 Range`,二选一即切，与请求是否带 Range 无关）：校准（未测镜像(无 5ms 成绩)>0 且候选全闲 → 每候选一片(区间÷候选数，直连腿同权)，同一批 5ms 窗同时出成绩）**或原生浏览器下载（无 Range——浏览器不会自己开并行，代理就是它唯一的并行来源）** → 每候选一片；带 Range 的请求默认单流直发，**但赶上校准窗口照样切**——冷启动首波第一条大段连接会被等分给全部候选，这是一次性的测速校准，不是贯穿下载全程的保证。**加速外包给下载器**——IDM 定连接数与波次，代理只做路由；原生浏览器下载无下载器可外包，并行由代理供给。

**校准重分配(切成才锁死)**：切片起 350ms 那次体检。三道先决，差一条整轮跳过：重分配开关开着(直连腿关)、这单还没切过、没有待发补发在途。段要进候选再过五关，全过才有资格谈切：已收到首帧(有速率样本)、体检点前刚被读过(离开视线的段速率信号不可信)、缓冲没顶格(顶格时排水速率失真)、还有剩余、近期滑窗速率>0。**V 读的是近期滑窗速率**(窗长与体检同节奏，历史停顿不进分母)——这是独立于 5ms 分配窗的第二本账。然后按各段纯排水速率找出全场最快的一段(含并列)——它本就满速跑，切下来重派反而亏，保留不切；其余段按"切多少"公式算切量 C，只切尾部 C 字节、留下 R−C 原地跑(不重爬)：

```
C = (R − P·V) × V_fast / (V_fast + V)
R = 本段剩余字节, V = 本段纯排水速率(B/s), V_fast = 全场最快速率, P = 接手方爬坡秒(取最快段那家的 ramp)
```

公式让"留下的 R−C 按 V 传完"与"切走的 C 交快流、爬坡后传完"同时到——谁也不拖，不造新尾巴。`R − P·V ≤ 0`(本段预计传完不比爬坡久) → C≤0 → 不切。切走部分交给 5ms ECT 挑家重派；原地跑的部分边界缩到切点，越界字节丢弃、到切点掐流(h2 连接回池不断)。**锁死语义：真切了字节才置锁**；整轮没人够格切(全组没样本/全够快/先决不满足)不置锁，350ms 后下一轮再试——"只做一次"说的是成功的那一刀，切死之后派发才交给 5ms 市场。单段即全场最快不切自己。停滞收尸独立进行，随时可收。日志打印留/切两端预计耗时，可直接核对是否同时完成。

**下载器波次下的全程行为**：IDM 等下载器动态分段——首波只开少数几条大段连接，中途再加。代理逐条派发，不保证每镜像一片：冷启动时所有源零历史零在途，ECT 分数完全并列、在途流数也并列 → TIE_ROTATOR 盲轮转摊开（此刻不知道谁快，纯撒样本让 5ms 账说话）；有成绩后按 (在途+新增)×5ms÷实收 派发，快源吃得多但被在途字节自动抬价，不会赢家通吃。**单流没有让位/转移**——切尾与补发只服务代理自管段；首波盲摊到慢源的大段只能靠下载器自己掐慢段重连来救（重连进来时 ECT 已有实测，自然落快源）。坏窗口：文件不大、总连接数少、首波摊到慢源且下载器不重连——此时退化单源速度。

失败降权两档：**硬错误(拒连/RST/坏回包)45 秒**、**超时类(拨号/首包/预算超时)15 秒**——慢不等于死；切片首切/补发失败同样降权，ECT 不反复踩死拨号家。

## 4. 失败分级(影响面从大到小)

| 层 | 触发 | 动作 |
| --- | --- | --- |
| 段 | 停滞 5 秒 / 206 错位 | 缩边界换家，缓冲不丢 |
| 镜像源 | 硬错误 45s / 超时 15s 降权 | 窗内不派新活，到期自愈 |
| 链 | 整链全灭(镜像参与时) | 熔断 60 秒快速失败 |
| 直连 IP | TCP / TLS / h2 失败 | 死亡退避，串发跳过 |

四层的区别是影响面：段影响一次请求，镜像源影响这家镜像参与的所有链，链影响该 chain_host 的全部候选派发，直连 IP 影响该 IP 上所有域名。混用会出两种事故——把抖动当死亡，或把风控当成功。

## 5. 媒体直连多路(白名单 7 域)

- 探片 10KB 记总长与媒体类别(10 分钟)；非媒体/不回 206 → 记不可切不再探
- 恒 N 段(目标 192KB，段数钳 4~8)，全部骑池内同一条直连通道——185.199 聚合水管恒定，多连接不加吞吐 → **关让位**，慢段只走停滞补发
- 并发闸 MAX_ACTIVE = 6(按响应体生命周期计数)；段失败同通道重试至多 3 次
- 镜像救援：图片链/视频链逐家续传(206 + 起点校验)，脚本无链 → 直连同通道偏移重拉；链全灭熔断 60 秒

## 6. 镜像请求卫生

- 身份头全剥：Cookie / Authorization / Referer / UA；注入恒定浏览器 UA(CF 系镜像拦非浏览器 UA，裸 Mozilla/5.0 一律 403)
- 模板:`{mirror}` `{url}` `{url_enc}` `{owner}` `{repo}` `{ref}` `{path}` 占位符；添加镜像时用法试探(5 种已知用法家族并发验货，首个命中存档)，无模板走前缀拼接
- 校准:小文件链逐 host 串行 TTFB 测速(跨链并发互相污染测量)，按毫秒重排；大文件域靠 ECT 用真实下载流量持续学习

## 7. 不变量

1. 镜像请求不携带任何身份头；恒定浏览器 UA
2. 206 段必须对刀口：起点错位、未带 Range 回 206、终点越界 = 静默截断，按失败换家
3. 合并只按偏移校验，不比内容；镜像无内容哈希是登记在案的边界，官方 SHA256 是唯一核验手段
4. 小文件流与大文件机器绝对解耦(big=false 零接触)
5. 补发按 ECT 挑家，不能挑"最空闲"
6. 熔断只拦镜像候选；零镜像时直连独走不连坐
7. 直连无镜像兜底时不设预算——直连是唯一的路
8. 让位、切片、补发的每一个退出路径都必须把字节账对平：缓冲不丢、区间不重叠、偏移不错位
