# GitPort GitHub —— GitHub 加速器

**中国大陆访问 GitHub 的本地加速器 —— 免插件、免服务器、后台约 12MB。**
push / 网页 / Release 下载 / raw / 头像全场景加速；git clone 走直连或你拼接的镜像 HTTPS 隧道，不进镜像竞速。其余网站流量完全不受影响。
直连流量本机直达 GitHub 官方边缘；镜像请求不携带任何身份头（Cookie/Authorization 进镜像前剥掉），URL 原样转发——签名/token 跟着 URL 走，介意者请勿启用第三方镜像或改用自建。

## 这是什么

本机跑一个代理（`127.0.0.1:7810`）+ 管理页面（`127.0.0.1:7811`），只接管 GitHub 系域名：

- **不查 DNS**：内置 GitHub 真实 IP 表（`routes.json`），DNS 污染免疫
- **连不上就换**：IP 按表逐个试，坏的垫底，单点故障只慢不掉
- **TLS 指纹是 Chrome 同款**：BoringSSL + 伪装 SNI，绕过针对明文域名的阻断
- **隧道握手首包分片**：CONNECT 透传把 ClientHello 拆成 2~3 段（首刀 1~16 字节随机切点、每段间隔 20~70ms 随机）再发，DPI 拼不齐 SNI（byedpi 同款思路，纯用户态）。总闸是编译期常量 `HELLO_SPLIT_ENABLED = true`，**没有运行时 A/B 开关**；退役的是 v1 为 docs 等子域专设的真名 SNI 腿，透传由客户端自持 SNI 与分片机制都还在跑
- **路由是一张表**：左边是出口（IP + 伪装身份 + 校验锚点），右边是域名（策略开关），中间靠节点的 `hosts` 声明"谁服务谁"；另外每对 (IP, 域名) 还有一套实测状态——421 拉黑、超时降权、风控冷却（成功只洗前两种，风控到期自愈），全部按边精确记账
- **连接复用到极限**：连接池按 IP 共享，一条 h2 连接混发多个 host 的流；**一 IP 一通道**（同 IP 第二条当场作废、递回池里现成的），host 级多通道靠候选里多个 IP 分落，全忙才补溢出临时通道（空闲即焚，句柄不外发）。请求路径一行 `pool::get_or_build`：从池取一条可用通道，池内按需建造——per-host 建造锁防雷群，一站管完。建造制度按域分流：内容域竞速（全部候选 IP 一 IP 一腿并发拨，按拨号耗时取最速入池，其余当场关闭）；会话域恒单通道（建连优先自己拨的那条，跨 IP 并发 SYN 是风控画像）；大文件域和那些不值得养专属通道的子域（只去 Fastly 边缘的 docs、support、resources、desktop、pages、skills、archiveprogram、socialimpact、raw.github.com、agent，加上超低频的 uploads、api.mcp，共 12 个）恒单腿串发，优先用池里现有的、没有才自建。串发有游标记步（上次驻留的 IP 优先起步、失败前移，纯内存态）；门房按「占用率」打分取最闲的那条接新流。通道持续存在，健康由驱动探活保证（内容域发 1 字节 Range 小请求、会话域发 PING，死了当场自摘出池），池里不留没人管的尸体
- **大文件分片竞速**：Release 附件按字节切段，镜像一家一份；**整包请求里直连入列两次**（主/副两条 h2 通道各领一段），并行拉；下载器同时发好几个 Range 时，把这些在途区间的字节加起来除以「镜像数 + 1」算出每段大小，大区间先占段位、小区间保底一段，不会每个请求都把全部镜像打满；文件再小也不设最小尺寸，照样按段位切；慢段尾巴自动让给最快的那条（ECT 时间槽派发：手里的字节 ÷ 上一窗实收）；候选全灭才失败。源码包（codeload / `/archive`）不支持分段，走主站池单流
- **README 大图/视频纯直连多段**：静态图片 CDN 的大图与嵌入视频不走常规镜像链，发 1 字节探片取总长后按约 192KB 切 4~8 段，**摊到池里多条直连通道上并发拉**（每条通道一个独立拥塞窗口，叠加同连接多 stream）；**先直连后镜像**——每段 5s 界，成功的段一字节不重拉，没拉完的部分由 routes.json `mirrors_small` 里的"图片"/"视频"链（工作台启用镜像自动带上，也可手改）按已交付偏移续传，镜像整段单流不切段。URL 查询串与凭据头原样保留，段请求只加 Range；镜像救援也失败才退回单流。详见 [工作原理](docs/ARCHITECTURE.md)

## 快速上手

1. 双击 `gitport-github.exe`（或 `.\gitport-github.exe -tray` 驻留托盘）
2. 首次启动在 exe 同目录自动生成 `ca.crt`/`ca.key`、`routes.json`、`settings.json` —— 所有开关默认全关
3. 打开工作台：先开「GitHub 分流接管」（写系统 PAC）→ 需要内容域直连/流式直通再开「MITM」（一键装证书根）

不开 MITM 也能用（纯透传加速）。系统代理接管在退出时自动还原；强杀残留由下次启动自愈。

## routes.json 里 `ips` 的每个键

`ips` 是"能用得上的出口清单"，一条记录就是一个出口（或一段同族的出口）。想加一条线路，往这里加一条即可：

```json
{
  "ip": "140.82.112-114.3-4",
  "sni": "baidu.com",
  "verify": "github.com",
  "hosts": ["github.com"],
  "latency": {"140.82.112.3": 580, "140.82.112.4": 553}
}
```

| 键 | 是什么 | 怎么写 |
|---|---|---|
| `ip` | 出口 IP。支持段范围：`140.82.112-114.3-4` 表示第三段 112~114、第四段 3~4，展开成 6 个 IP | 单个 IP 或范围，范围最多展开 64 个 |
| `sni` | 握手时报给墙看的**假名字**，骗它放行。跟你实际要访问的站点无关 | 现在全线都是 `baidu.com` |
| `verify` | 校验对面证书用的**锚点域名**。只要求证明"对面真的是 GitHub"，不要求它等于你要访问的域名 | 留空 = 按你访问的域名校验（默认，通常够用）；只有留空连不上才填，见下一节 |
| `hosts` | 这个出口**服务哪些域名**。写的是 `hosts` 块里的键（如 `github.com`、`*.githubusercontent.com`），不是逐个子域 | 一个出口可以服务多个域名，一条连接就能混发 |
| `latency` | 建连用时（毫秒），按具体 IP 记 | 运行时每次真实拨号自动回写（内存态，退出时落盘）；手改不用管，删掉就垫底 |

两条规矩：

- **域名只在一边写**。`hosts` 块只写"有特殊策略"的域名（比如 `content` / `fallback: mirror`）；普通域名靠节点的 `hosts` 声明就够了，程序启动时会自动补回，落盘时也把它们省略。所以看不到某个域名不代表它没被代理。
- **两边的对应关系**。节点声明了某个域名、`hosts` 块没写 → 启动时自动补一行默认配置，所以文件里看不到它；反过来，`hosts` 块写了某个域名、却没有任何节点服务它 → 这个域名没有出口，请求直接走兜底。

### `verify` 什么时候要填

**默认不填。** 空 = 拿你访问的域名当锚点，绝大多数 IP 直接能过。

证书和「这个 IP 能服务哪些域名」是两件不同的事：握手时我们报的是假 SNI（`baidu.com`），服务器只发一张默认证书；真正的业务路由走 h2 的 `:authority`。所以一个域名可以在这个 IP 上正常取到内容，但它的名字**不在默认证书的 SAN 里**——这时留空会握手失败，而且是我们主动中止，不是对方拒绝服务。

只有一种情况要填：**新加的 IP 留空连不上**。日志会打 `证书校验失败` 并附现成命令，照做取出 SAN，填其中任意一个域名即可（不必等于你要访问的域名）；填对了，同一个 IP 立刻可用。已知各段的锚点见 [高级配置](docs/CONFIG.md) 的「认 IP 速查」。

## 已知边界

| 做不到 | 原因 | 应对 |
|---|---|---|
| macOS / Linux | 系统代理、托盘、剪贴板全调 Windows API（winreg / WinInet） | macOS 推荐 Watt Toolkit / Clash Verge |
| 大文件上传快 | push 与单附件都是单流协议，一条 TCP 的吞吐就是天花板（本机实测约 119KB/s）；代码里没有限速，换链路会变 | 多附件并发；优先走 release 附件上传（本机实测直拨约 1.3MB/s） |
| 一劳永逸 | GitHub 边缘 IP 会迁移 | 种子补缺 + DNS 兜底腿自愈；极端情况手改 `routes.json` |
| 零门槛 | MITM 需装本地根证书 | WebUI 一键安装；不装也能用 |
| 加速所有网站 | 只路由 GitHub 系域名 | 其他站点用通用代理 |
| 镜像请求**不带任何身份头** | Cookie/Authorization 进镜像前剥掉；URL（含 302 落点签名/token）原样转发给镜像——知情取舍，介意请用自建镜像或不启用镜像 | 介意私库内容/签名 URL 经手第三方时，在工作台临时关掉镜像或换自建（设置页有部署教程） |
| raw/头像偶发被掐 | GFW 对 Fastly 内容边缘间歇阻断 | 内容域熔断 + 镜像链自动接管 |
| 透传遇会话级风控页会持续 | 经验性观察：透传看不见响应状态码，代码里没有「会话级风控页」检测，只有 MITM 侧能识别 403 restricted / 400 Whoa 拦截页并换边 | 切 MITM（连接池驻留、零 IP 漂移）或等风控过期 |
| schannel 系 CLI 走 MITM | 本地签发的叶子证书确无 OCSP/CRL/AIA 扩展；「Windows 吊销检查硬失败」是平台行为，代码侧只能确认前者 | `curl --ssl-no-revoke`；git 关 `schannelCheckRevoke`；浏览器无感 |
| README 大图只切静态图片 CDN | 会话域与 `/raw/` 302 第一跳不在白名单；≥512KB 且为 `image/*` 才切；池里没有现成直连连接、或任一段没回规范的 206，都退回单流 | 小图、非图片、池冷时本来就该走单流；不规范的第三方 206 会走补发而不是拼错字节 |
| 根证书只签 GitHub 域 | 签发前校验域名在受管表内，其他域名一律拒签 | 既是限制也是保护：装了这个根证书，也只有 GitHub 系域名会被解开 |
| 管理界面写接口要带标记头 | 防跨站伪造，无 Origin 的请求需带 `X-GitPort-Request: 1` | 浏览器工作台无需处理；curl 调用加一个头即可 |

## 常见问题

- **push 大包慢？** push 是单流协议，一条 TCP 的吞吐就是天花板（本机实测约 119KB/s，代码里没有限速）；流式直通保证不 502，中断后整体重传。
- **raw 偶发 6~8 秒？** 直连池到 Fastly 内容边缘间歇受阻（池内握手统一用伪装 SNI；v1 的白名单真名腿已退役，现在只有 CONNECT 透传由客户端自持 SNI、全灭 DNS 兜底腿用真名，跟这里无关）；内容域熔断 + 镜像兜底已就位，自动恢复。
- **浏览器报证书风险？** MITM 开了但根证书未装/浏览器未重启；WebUI 一键装根后重启浏览器。
- **端口冲突？** `.\gitport-github.exe -port 7812 -webui 7813`。
- **页面显示「暂时不可用」？** 封锁窗口期，8 秒自动刷新，窗口一过即恢复。
- **双击 exe 没反应？** 若旧实例界面已死（托盘无图标、窗口出不来），它会收到点击后自动退出，新实例约 2 秒内接管；若旧实例还活着，会弹「已在运行」提示——去看系统托盘。

## 它为什么对 GitHub 友好

常见加速器是"多开连接多轰几遍"。这个项目每一层反过来，都在帮 GitHub 省资源——既是设计立场，也是它和同类工具的差别：

- **遥测拦截**：GitHub 前端遥测占 api.github.com 约 75% 的请求（Datadog RUM / 心跳），本地直接读掉回 204，一个字节不发往上游
- **压缩双档协商**：`github.com` / `api.github.com` 按客户端声明重写协商头——接受 br 的发 "br, gzip" 双档（实测主站不吃 br，单发 br 曾让每页 320KB 裸奔五天没人发现）；其余域名放行浏览器原生 br/zstd
- **页面缓存三层**：资产（JS/CSS）浏览器 immutable 缓存直出（代理零参与——实测 48 分钟 132 个资产请求缓存命中 0 次，机制已删）；页面数据（文件列表/提交/侧栏）走 XHR 实时直通不缓存；HTML 按仓库快照——列表页会话内秒回，**仓库首页跨会话快照 7 天**（底稿+分段增量存储，过期交旧+后台静默重拉，发版在窗口内隐身），首页骨架单独 7 天。强制刷新用 Ctrl+F5（F5 会读缓存）。搜索页按 Accept 分 JSON/HTML 两把钥匙、`p=1` 归一化、限流骨架拒存。细账见 [页面缓存](docs/CACHE.md)
- **头像入口 302 记忆**：GitHub 的头像入口是「302 跳转 + no-cache」，浏览器每次渲染都要重问一遍跳转（260-310ms × 十几个并行）。代理记住跳转目标本地直答，浏览器行为不变、来回归零
- **数据层验活的串发拨号**：没有后台定时全量测速（那种循环才是真给边缘添堵），IP 死活全凭真实请求验出来，失败即换、成功即驻留

## 选哪个镜像

不想挑就不用挑：**全新安装内置 8 家复测精选的公共镜像**（2026-11-14 双轮拨测按耗时排序，788ms~1070ms），开箱即用。

- 快的没必要再帮着宣传，公益服务扛不住白嫖流量；
- 工作台里支持填多个镜像：图片链用「校准」按钮按响应头实测排位，大文件下载由代理按实时吞吐动态选家——链序只决定失败顺延次序；
- 嫌慢随时删掉换别的，或者干脆自建一个 CF Worker（设置页有完整部署教程与代码）。

## 镜像与身份(知情须知)

镜像请求**不携带任何身份头**：Cookie/Authorization 在进镜像前剥掉，镜像拿不到你的登录态。

但 **URL 本身会原样到达镜像**——包括 GitHub 302 落点里的 `sig`/`jwt` 签名和私库 raw 地址里的 `token`（签名 = 一小时有效的提货凭证）。代理分不出仓库是公共还是私有，也不会替你拦：这是"要不要用第三方镜像"的知情取舍。

- **自建的 Cloudflare Worker(代码在设置页)**：日志在你手里，没有任何第三方经手，随意用；
  - **公益镜像(gh-proxy.org 等)**：通常会记录请求 URL——介意私库文件经手第三方的话，下载私库内容时临时关掉镜像或改用自建。
  - **自己拼接的镜像 clone URL**（`https://某镜像/https://github.com/...`）：代理会放行这条 HTTPS 隧道（仅限 443、纯透传不解不缓存；环回/私网/CGNAT/链路本地/组播/保留地址与非 443 端口仍 502），镜像站看到什么同上。注意 clone 本身**没有加速**——走这类链接或原 URL 都是直连速度，快慢取决于镜像站本身。

简单法则：**全公共仓库随意；常下私人内容 → 自建镜像，或按需开关镜像。**
